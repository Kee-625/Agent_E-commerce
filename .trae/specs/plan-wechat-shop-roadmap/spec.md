# 微信小店「腰腹热敷带」店铺发展路线 Spec

## Why
店铺在微信小店经营腰腹热敷带，但主营类目为「运动户外」。商品属性与类目归属不匹配，会同时影响商品审核与资质路径、可参与的活动与流量场，以及内容种草的人群一致性。用户需要的不是「再上几个新品」，而是先明确店铺未来 6–12 个月到底以哪条主线发展。

## What Changes
- 明确「主营类目」与「商品矩阵」的匹配关系，给出类目归属建议，并区分已核实规则与需用户确认的资质项
- 产出不超过三条发展路径的对比（健康个护主线 / 运动户外主线 / 双线并行），给出唯一推荐及「什么条件下应改选」
- 输出 12 个月阶段路线（0–3 / 3–6 / 6–12 月），含商品矩阵、内容与私域承接、北极星指标与止损/加码闸门
- 交付 HTML 主报告 + 配套 Markdown 执行清单 + 对话内可视化 + 对话结论摘要
- 不含店铺后台改类目、上架、投放等执行动作（属于交接范围）

## Impact
- Affected specs: 无（新建）
- Affected code: 无代码变更；交付物输出至 `/workspace`

## 工作焦点与假设（启动前声明）
| 项 | 取值 | 状态 |
|---|---|---|
| 市场家族 | 中国国内（微信生态：视频号/公众号/小程序/私域） | 用户明示 |
| 主类目 | 运动户外 | 用户明示 |
| 在售商品 | 腰腹热敷带 | 用户明示 |
| 热敷带类目归属 | 个护健康/家居日用/家用电器/医疗器械候选，以平台类目表为准 | 需核实 |
| 店铺经营数据 | 未提供 GMV、转化、退款、复购、毛利 | 假设/待补 |
| 决策周期 | 12 个月，分 3 段 | 按决策选取 |

## ADDED Requirements

### Requirement: 类目—商品匹配诊断
系统 SHALL 说明腰腹热敷带在微信小店的可能类目归属，标注「已核实/需核实」，并说明「主营类目与商品不匹配」的具体后果：商品审核与上架、类目资质、活动报名、视频号挂车与直播权限、流量分发、违规风险。
#### Scenario: 现状盘点
- **WHEN** 用户提供店铺主类目与在售商品
- **THEN** 输出类目归属候选、匹配结论、风险等级，以及需用户确认的资质信息（如是否涉及电加热、是否宣称理疗功效）

### Requirement: 多条发展路径对比与推荐
系统 SHALL 给出不超过三条路径，每条覆盖目标人群、商品矩阵、内容与渠道打法、投入强度、见效周期、主要风险，并明确推荐一条及适用前提。
#### Scenario: 路径选择
- **WHEN** 用户未明确未来定位
- **THEN** 输出路径对比表与推荐结论，说明推荐成立的条件，以及何种信号出现时应改选其他路径

### Requirement: 阶段路线与指标
系统 SHALL 输出 12 个月分阶段路线，每阶段包含目标、关键动作、责任角色（非具体人名）、指标与止损/加码条件。
#### Scenario: 路线落地
- **THEN** 每个阶段至少包含 1 个北极星指标与 1 个风险闸门

### Requirement: 证据与假设标注
系统 SHALL 区分「实测 / 溯源 / 推导 / 假设 / 未知」，不得编造店铺数据、平台费率、类目规则、市场规模或竞品表现。
#### Scenario: 缺数据
- **WHEN** 用户未提供后台经营数据
- **THEN** 以公开来源与显式标注的假设推进，并在结论中说明该缺口对置信度的影响

### Requirement: 交付形态
系统 SHALL 交付 HTML 主报告（由系统 html-report 技能渲染）、一份配套 Markdown 执行清单、一个对话内可视化、以及对话结论摘要；四者事实、口径与推荐一致。
#### Scenario: 交付完成
- **THEN** 用户可打开 HTML 报告通读，并用 Markdown 清单执行首月动作，无需再回看对话
