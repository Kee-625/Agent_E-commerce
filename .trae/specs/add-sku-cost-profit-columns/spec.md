# 商品管理成本利润模型 Spec

## Why
「商品管理」子表目前只有 产品简称 / 产品ID / SKU名称 三列，无法回答“这个 SKU 到底能净赚多少钱”。需要把最终售卖价、各项成本和平台/税费规则沉淀进表内，并用公式直接算出单件净利与净利率。

## What Changes
- 在「商品管理」现有 A:C 三列右侧扩展 14 列，覆盖售价、成本、佣金、平台扣点、退货、所得税、净利
- 为每个数据行写入净利与净利率公式，公式带空值保护，未填售价的行不显示 0 或错误
- 平台扣点率、所得税率以数值（0.05）落在行内，便于后续调整
- 公式预填至第 50 行，新增 SKU 时只需填数即可自动计算
- 前 3 列的唯一键语义（产品ID + SKU名称）保持不变

**BREAKING**：无（仅在 A:C 右侧追加列，不移动、不覆盖既有列）。

## Impact
- Affected specs: 微信小店台账维护（`establish-shop-ledger-workflow`）的「商品管理写入规范」，本 Spec 为其右侧扩展，不改变原三列规则
- Affected code: 无业务代码；使用腾讯文档 sheet-mcp 写入
- 涉及资源：文档 file_id `HGHIXNuwfGoa`，子表 `商品管理` sheet_id `BB08J2`

## ADDED Requirements

### Requirement: 成本利润列结构
「商品管理」SHALL 在 A:C 之后固定以下列序，表头位于第 1 行：

| 列 | 字段 | 说明 |
|---|---|---|
| A | 产品简称 | 既有 |
| B | 产品ID | 既有 |
| C | SKU名称 | 既有 |
| D | 最终售卖价 | 扣除平台所有优惠后的实收单价，唯一计价基准 |
| E | 商品成本 | 单件进货/生产成本 |
| F | 运费险 | 单件保费 |
| G | 达人佣金率 | 百分比数值，如 0.2 |
| H | 达人佣金 | 公式，= D × G |
| I | 平台扣点率 | 固定 0.05（5%），可按行调整 |
| J | 平台扣点 | 公式，= D × I |
| K | 退货率 | 百分比数值，如 0.1 |
| L | 退货成本 | 公式，= K × 3（退货一次成本 3 元） |
| M | 所得税率 | 固定 0.05（5%），可按行调整 |
| N | 所得税 | 公式，按毛利计提 |
| O | 其他成本 | 预留，用户自行填写的额外成本 |
| P | 单件净利 | 公式，见下方计算规则 |
| Q | 净利率 | 公式，= 单件净利 ÷ 最终售卖价 |

#### Scenario: 查看某 SKU 的列
- **WHEN** 用户打开「商品管理」
- **THEN** 第 1 行依次显示 A 到 Q 共 17 个表头，字段名与上表一致

### Requirement: 净利计算公式
每个数据行 r（r ≥ 2）SHALL 使用以下公式，且全部带空值保护（D 列为空时整行结果留空）：

- 达人佣金 H：`=IF($D{r}="","",$D{r}*$G{r})`
- 平台扣点 J：`=IF($D{r}="","",$D{r}*$I{r})`
- 退货成本 L：`=IF($D{r}="","",$K{r}*3)`
- 所得税 N：`=IF($D{r}="","",($D{r}-$E{r}-$F{r}-$H{r}-$J{r}-$L{r}-$O{r})*$M{r})`
- 单件净利 P：`=IF($D{r}="","",$D{r}-$E{r}-$F{r}-$H{r}-$J{r}-$L{r}-$O{r}-$N{r})`
- 净利率 Q：`=IF($D{r}="","",IFERROR($P{r}/$D{r},0))`

所得税基数 SHALL 为毛利，即 售价 − 商品成本 − 运费险 − 达人佣金 − 平台扣点 − 退货成本 − 其他成本，再乘以所得税率。

#### Scenario: 完整填数后得出净利
- **WHEN** D=99、E=30、F=2、G=0.2、I=0.05、K=0.1、M=0.05、O=0
- **THEN** H=19.8，J=4.95，L=0.3，毛利=41.95，N=2.0975，P=39.85，Q≈0.4026（约 40.3%）

#### Scenario: 只填了 SKU 未填售价
- **WHEN** D 列留空
- **THEN** H、J、L、N、P、Q 均显示为空，不出现 0、#DIV/0! 或其他错误值

### Requirement: 参数填写方式
商品成本、运费险、达人佣金率、退货率、其他成本、最终售卖价 SHALL 由每行独立填写，不同 SKU 互不影响。平台扣点率与所得税率 SHALL 预置为 0.05，允许按行覆盖。

#### Scenario: 三个 SKU 成本不同
- **WHEN** 一条装、俩条装、三条装分别填写各自的商品成本
- **THEN** 三行的净利各按本行成本计算，互不串行

### Requirement: 公式预填范围
公式列 SHALL 预填至第 50 行，使后续新增 SKU 只需填数即自动计算；新增行不得覆盖已存在的业务数据。

#### Scenario: 新增第 20 行 SKU
- **WHEN** 用户在第 20 行填入产品与售价
- **THEN** H/J/L/N/P/Q 自动得出结果，无需补公式

### Requirement: 既有数据保护
本变更 SHALL 只写入 D1:Q1 表头与 H/J/L/N/P/Q 公式列，以及 I、M 的默认费率；不得改动 A:C 的既有内容与行序。

#### Scenario: 写入后核对既有商品
- **WHEN** 扩展列完成
- **THEN** 第 2–4 行的产品简称、产品ID、SKU名称与变更前完全一致
